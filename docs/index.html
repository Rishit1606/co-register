    How the agents get to a plan

    1. Share. Each agent announces which requirement categories its student still needs and when they are free. It never says why a time is blocked.
    2. Find. The course finder intersects those categories and looks for a class that counts for every major.
    3. Negotiate. Agents take turns proposing sections. The others answer accept or decline, with no reason. When nobody has a proposal left, every agent privately drops its least important preferences, one level at a time.
    4. Get seats. If the section is short on seats, a breadth-first search finds the shortest swap cycle through students who hold seats. Each of them confirms their part.
    5. Confirm. Each student reads a private briefing and answers yes or no. One no sends everyone back to step 3 without that section.

    What is real and what is mock

    • The negotiation you see here is the real engine. It is the same Python code that runs in the terminal, running in your browser.
    • The courses, seat counts, students and seat holders are mock data. It does not connect to a real class search and cannot register anyone.
    • The agents are objects inside one program, not separate devices. A share policy checks every message against a field whitelist and scans it for that student's private values, and an audit scans the whole log at the end.
    • "Peek inside" shows what each agent's own student would see on their screen. Those notes are recorded beside the messages, never inside them, and the audit checks that.
    • No AI model makes any decision. The agents use set intersection, backtracking search and graph search. An optional language model can reword a few public summary lines, and it is off here.
    • After a relaxation round, the other agents can tell that someone dropped a preference. They cannot tell who it was or what it was.
